The Core Objective

Trace a 32-bit virtual address stream into its corresponding physical address destination using a multi-level page table schematic layout.

The Problem Hook: Base-and-bound is fast — one addition, one comparison per memory access. But it requires every process to occupy a contiguous block of physical RAM. After an hour of running, the memory looks like Swiss cheese — plenty of total free space, but scattered across tiny holes. A new process needs 8 MB, and no single hole is large enough. How do we give every process a perfectly "clean" 8 MB block without moving anything else?

🎒 EVERYDAY SIMPLIFIED: THE INDEX CARD CHEAT-SHEET

The Page Table Metaphor

📚🗂️🔍
The Narrative

Imagine a giant encyclopedia that has been ripped apart — every page torn out and scattered randomly across drawers in a huge room. To read the book in order, you need an index card cheat-sheet. The book is written in logical order: Chapter 1 is on Page 0, Chapter 2 on Page 1. The index card says: "Page 0 is in Drawer #4" and "Page 1 is in Drawer #99." You can read smoothly because your index map fixes the scattered physical chaos transparently.

Execution Path

The index card is the page table. Each entry maps a virtual page number to a physical frame number. Any page can go in any frame.

Micro-Accessibility Context

The page table is the source of paging's flexibility — and the source of its cost (each entry is a memory lookup).

🎒 EVERYDAY SIMPLIFIED: THE STANDARDIZED BOXES

The Page/Frame Metaphor

📦📦📦
The Narrative

Imagine a shipping warehouse where every crate must be exactly the same size — 4 KB per crate. No jumbo crates, no half crates. Each process gets an unlimited number of crates, and any crate can go in any shelf slot of the same size. You never have "hole" problems because every empty slot fits any crate.

Execution Path

Virtual memory is split into fixed-size pages. Physical RAM is split into fixed-size frames. The two sizes are identical (typically 4 KB). Any page can go in any frame — no contiguity required.

Micro-Accessibility Context

Uniform size eliminates external fragmentation entirely. No hole is ever "too small" — every hole is exactly the right size.

🎒 EVERYDAY SIMPLIFIED: THE TWO-PART ADDRESS

The Bit-Split Metaphor

✂️🔢🔀
The Narrative

Imagine every address the CPU generates is a 32-bit number — a long string of 0s and 1s. Paging splits this number with a virtual pair of scissors into two parts: a big page number (the top 20 bits) and a smaller offset (the bottom 12 bits). The page number tells you which page you are on; the offset tells you where inside that page you are.

Execution Path

The MMU extracts the page number from the high bits, looks it up in the page table, and appends the unchanged offset to the resulting frame number.

Micro-Accessibility Context

This bit-splitting is what makes paging translation fast — it is pure hardware bit manipulation, no arithmetic.

🎒 EVERYDAY SIMPLIFIED: THE TWO-TRIP TAX

The Performance Tax Metaphor

🚶🚶💸
The Narrative

Base-and-bound was a single taxi ride: logical address → physical address. Paging is a two-trip taxi ride. First, the taxi takes you to the page table (in RAM) to look up the translation. Then a second taxi takes you to the actual data. Every memory access is now twice as expensive — the CPU spends half its time walking page tables.

Execution Path

Standard paging requires two physical RAM accesses per logical access: one to read the page table entry, one to read the actual data. This doubles memory latency.

Micro-Accessibility Context

This 2× tax is precisely why the TLB (L12) exists — to cache recent translations and bypass the page table walk.

🎒 EVERYDAY SIMPLIFIED: THE PAGING SUITE

The Summary Metaphor

✅ What Paging Provides

No external fragmentation (all blocks same size). Flexible allocation (any page to any frame). Simple bit manipulation. No need to relocate processes.

❌ What It Costs

2× memory access latency (page table walk + data access). Internal fragmentation (last page may be partially used). Larger page tables for large address spaces.

Paging trades external fragmentation for extra latency and internal fragmentation. This is a good trade — but the latency cost is so painful that L12 (TLB) is required to make paging practical.

💻 SYSTEMS COHESION: THE FIXED-SIZE CHUNKS

Pages and Frames

Page (Virtual)

A fixed-size contiguous block of virtual address space allocated by the compiler and operating system kernel.

Typical size: 4 KB (4096 bytes).

Property: Virtual pages are numbered 0, 1, 2, ... starting from address 0 for each process.

Ownership: Each process has its own page numbering — Process A's page 5 is different from Process B's page 5.

Frame (Physical)

A physical, hardware-wired block of real RAM storage matching the exact byte dimensions of a system page slot.

Typical size: 4 KB (same as page).

Property: Physical frames are numbered 0, 1, 2, ... across the entire RAM chip.

Ownership: Each frame is uniquely owned at any instant — either by one process's page, or free (or shared by the kernel).

Key insight: Page size must equal frame size. This is what makes "any page can go in any frame" work — the units are interchangeable.

The Formula

page_number = virtual_address >> 12 (shift right by offset bits)

offset = virtual_address & 0xFFF (mask low 12 bits)

With 4 KB pages: 12 bits for offset (2¹² = 4096). Remaining bits for page number. A 32-bit address space → 20-bit page number → up to 2²⁰ = 1,048,576 pages per process.

💻 SYSTEMS COHESION: THE PAGE TABLE STRUCTURE

The Page Table — Full Translation Map

Page Table Definition

The authoritative data matrix structure held in kernel space that maps a process's virtual page numbers to real hardware frame slots.

Where it lives: In physical RAM, at an address the OS stores in the CPU's CR3 register.

What it contains: One entry per virtual page. Each entry holds: physical frame number + valid bit + protection bits (read/write/execute) + dirty bit + accessed bit.

💻 SYSTEMS COHESION: THE THREE-STEP TRANSLATION

The MMU Translation Mechanism

Step 1 · Extract

The MMU receives a logical address from the CPU. It splits it into:

· Page number p (top bits)

· Offset d (bottom 12 bits)

This is pure bit extraction — no arithmetic, just a shift and mask.

Step 2 · Lookup

The MMU uses page number p as an index into the process's page table.

· If valid = 0 → page fault (page not in RAM — L13 will handle this)

· If valid = 1 → retrieve frame number f

This requires one extra RAM access.

Step 3 · Assemble

Concatenate the retrieved frame number f with the unchanged offset d:

physical = (f << 12) | d

The offset is never modified — it indexes within the page, which is identical in both virtual and physical space.

Total cost: One extra RAM access per memory operation (the page table lookup). This is the "two-trip taxi ride" — the tax paging pays for its flexibility.
💻 SYSTEMS COHESION: THE WORKED MAPPING EXAMPLE

Walking a Full Translation

The Setup

16-byte virtual address space with 4-byte pages (simplified for teaching — real systems use 32-bit addresses and 4 KB pages).

4-bit address = 2-bit page number + 2-bit offset. Page table: {0→5, 1→7, 2→1, 3→3}

Example 1: VA = 0b 1101

Split: page = 11₂ = 3, offset = 01₂ = 1

Lookup: page 3 → frame 5 (101₂)

Assemble: 101₂ || 01₂ = 10101₂ = 0x15 (21 decimal)

Example 2: VA = 0b 0110

Split: page = 01₂ = 1, offset = 10₂ = 2

Lookup: page 1 → frame 7 (111₂)

Assemble: 111₂ || 10₂ = 11110₂ = 0x1E (30 decimal)

Example 3: VA = 0b 0011

Split: page = 00₂ = 0, offset = 11₂ = 3

Lookup: page 0 → frame 5 (101₂)

Assemble: 101₂ || 11₂ = 10111₂ = 0x17 (23 decimal)

Note: the offset d is identical in both virtual and physical addresses. Only the page number changes.

🔗 SYSTEM PIPELINE: FIXES BASE-AND-BOUND

Core System Cohesion — Solves L10's Fragmentation

L10's Fatal Flaw

Base-and-bound required contiguous physical blocks. External fragmentation meant total free memory could be sufficient but unusable — no single hole large enough.

L11's Solution

Paging splits memory into uniform 4 KB units. Any page fits any frame. External fragmentation is eliminated — a hole is never "too small" because all holes are exactly the right size.

The Trade-off

Paging introduces two costs:

1. 2× memory access latency (page table walk + data access)

2. Internal fragmentation (last page may be partially used)

When It's Worth It

Almost always. The 2× latency is hidden by TLB caching (L12). The internal fragmentation cost is minor (average 2 KB per process on 4 KB pages). The flexibility gain is enormous.

🔗 SYSTEM PIPELINE: FEEDS INTO TLB AND DEMAND PAGING

Core System Cohesion — Feeds Into L12 & L13

L12 (TLB Acceleration)

Paging's 2× latency is unacceptably slow. The TLB caches recent page table translations in fast CPU registers — a TLB hit reduces the cost to a single memory access. Without the TLB, paging would be too slow for production systems.

L13 (Demand Paging)

Once we have a page table with valid bits, we can mark pages as not yet loaded. When a process touches such a page, the kernel loads it from disk on demand. This is the foundation of virtual memory — programs larger than physical RAM.

The Page Fault Exception

The valid = 0 case is what L13 calls a page fault. The kernel's page fault handler loads the page from disk (or swap), installs the page table entry, and retries the instruction.

The Module 3 Arc

L10 (base-and-bound) → L11 (paging) → L12 (TLB) → L13 (demand paging). Each fixes the previous layer's fundamental problem. Together they form the complete memory virtualization stack.

🔍 COMPREHENSIVE CRITIQUE: PAGING STRATEGIES

Paging Strategies Across the Five Paradigms

Monolithic Paging

Page tables managed in Ring 0, page faults handled by in-kernel page fault handler. Fastest — but the kernel's memory subsystem is a large, complex, vulnerability-prone area. Bugs in the page fault handler are security-critical.

Microkernel Paging

Page fault handling can be delegated to a user-space pager service. The kernel handles only the minimum (TLB flush, page table installation), while a user-space server decides which page to load and from where. Slower — but the pager is isolated.

Layered Paging

Hardware MMU translates virtual → physical. Kernel maintains page tables. User-space memory allocators manage the heap. Each layer has clear responsibility and testable interfaces.

Modular Paging

Different page table formats supported via modules — 32-bit vs 64-bit, 4-level vs 5-level, huge pages vs standard pages. Linux supports all of these via modular configuration.

Hybrid Paging

Standard 4 KB paging for most memory, with huge pages (2 MB or 1 GB) available for high-throughput workloads (databases, HPC). The TLB footprint for huge pages is dramatically smaller — one entry covers 2 MB instead of 4 KB.

🏷️ SYSTEM LEXICON: MASTERING THE PAGING VOCABULARY

Base Paging Terms

Term 01 · Page

A fixed-size contiguous block of virtual address space allocated by the compiler and operating system kernel. Typically 4 KB. The virtual address space of each process is divided into pages numbered from 0, providing a clean, uniform abstraction over the messy physical layout of RAM.

(The standardized shipping crate — every crate is exactly the same size.)

Term 02 · Frame

A physical, hardware-wired block of real RAM storage matching the exact byte dimensions of a system page slot. Frames are numbered sequentially across the entire physical memory chip, and at any instant each frame is either allocated to a specific page or free.

(The shelf slot — every slot is exactly the same size, ready to hold any crate.)

🏷️ SYSTEM LEXICON: MASTERING THE PAGING VOCABULARY

Advanced Paging Terms

Term 03 · Page Table

The authoritative data matrix structure held in kernel space that maps a process's virtual page numbers to real hardware frame slots. Each entry contains the physical frame number plus control bits (valid, protection, dirty, accessed). The base address of the active page table is stored in the CPU's CR3 register.

(The index card cheat-sheet that maps "virtual Page 0" to "physical Drawer #4".)

Term 04 · Internal Fragmentation

Wasted memory space that occurs when a process requests a buffer that does not completely fill out the final allocated fixed-size page block boundaries. A 5 KB allocation occupies two 4 KB pages (8 KB total), wasting 3 KB in the second page. Average waste is roughly half a page per process — but it is bounded and predictable, unlike external fragmentation.

(The last shipping crate is only half-full, but you still pay for the whole crate.)

Term 05 · Page Fault

A hardware trap raised when the MMU encounters a page table entry with valid = 0. The kernel's page fault handler takes over, determines whether the fault is legitimate (page not yet loaded) or invalid (access to unmapped memory), and either loads the page from disk or terminates the process with SIGSEGV. Detailed coverage in L13.

(The empty shelf slot — the crate has not been delivered yet.)

💻 CODE DISSECTION: C PAGE TABLE SIMULATOR

Simulating Bit-Level Paging Translation

// Simulating bit-level paging address translation in C
// 32-bit virtual address, 4 KB pages (12-bit offset, 20-bit VPN)
#include <stdio.h>
#include <stdint.h>

#define PAGE_SIZE       4096       // 4 KB pages
#define OFFSET_BITS     12         // log2(4096) = 12
#define OFFSET_MASK     ((1 << OFFSET_BITS) - 1)  // 0xFFF
#define PAGE_TABLE_SIZE 1024       // Simplified: 1024 entries

// A simplified page table — one entry per virtual page
typedef struct {
    uint32_t frame_number;
    int      valid;
    int      writable;
    int      accessed;
} PageTableEntry;

typedef struct {
    PageTableEntry entries[PAGE_TABLE_SIZE];
} PageTable;

// The MMU translation — splits address, looks up page table, assembles
int translate(PageTable* pt, uint32_t virtual_addr,
              uint32_t* physical_out) {
    // Step 1: Extract the bit fields
    uint32_t vpn    = virtual_addr >> OFFSET_BITS;
    uint32_t offset = virtual_addr & OFFSET_MASK;

    // Step 2: Lookup in page table
    if (vpn >= PAGE_TABLE_SIZE) {
        printf("  VA 0x%08X: VPN %u out of range\n", virtual_addr, vpn);
        return -1;
    }

    PageTableEntry* e = &pt->entries[vpn];
    if (!e->valid) {
        printf("  VA 0x%08X: VPN %u NOT PRESENT → PAGE FAULT\n",
               virtual_addr, vpn);
        return -2;
    }

    e->accessed = 1;

    // Step 3: Assemble the physical address
    *physical_out = (e->frame_number << OFFSET_BITS) | offset;

    printf("  VA 0x%08X (VPN=%u, off=0x%X) → Frame %u → PA 0x%08X\n",
           virtual_addr, vpn, offset, e->frame_number, *physical_out);
    return 0;
}

int main() {
    PageTable pt = { 0 };

    // Set up some mappings (VPN → physical frame)
    pt.entries[0]  = (PageTableEntry){ .frame_number = 5,  .valid = 1, .writable = 1 };
    pt.entries[1]  = (PageTableEntry){ .frame_number = 12, .valid = 1, .writable = 1 };
    pt.entries[2]  = (PageTableEntry){ .frame_number = 47, .valid = 1, .writable = 0 };
    pt.entries[3]  = (PageTableEntry){ .frame_number = 8,  .valid = 1, .writable = 1 };
    pt.entries[4]  = (PageTableEntry){ .frame_number = 3,  .valid = 1, .writable = 0 };
    // VPN 5 is not present — will trigger a page fault
    pt.entries[5]  = (PageTableEntry){ .frame_number = 0,  .valid = 0, .writable = 0 };

    printf("=== Bit-Level Paging Translation ===\n\n");

    // Test various virtual addresses
    uint32_t test_addresses[] = {
        0x00000123,  // VPN=0, offset=0x123 → frame 5
        0x000017FF,  // VPN=1, offset=0x7FF → frame 12
        0x00002000,  // VPN=2, offset=0 → frame 47
        0x00003456,  // VPN=3, offset=0x456 → frame 8
        0x00004ABC,  // VPN=4, offset=0xABC → frame 3
        0x00005000,  // VPN=5 → PAGE FAULT (not present)
    };

    uint32_t pa;
    for (int i = 0; i < 6; i++) {
        int result = translate(&pt, test_addresses[i], &pa);
        if (result == -2) {
            printf("  → Kernel would handle the fault (L13)\n");
        }
    }

    return 0;
}

Use code with caution.

💻 CODE DISSECTION: TRACING PAGING BIT ARITHMETIC

Walking the Paging Translation Trace

vpn = virtual_addr >> OFFSET_BITS

Step 1a. Right-shift by 12 extracts the top 20 bits. For VA 0x000017FF, this gives 0x1 (VPN = 1). Pure bit extraction — no arithmetic.

offset = virtual_addr & OFFSET_MASK

Step 1b. AND with 0xFFF extracts the low 12 bits. For VA 0x000017FF, this gives 0x7FF (offset = 2047). Bit mask — no division.

if (!e->valid)

The page fault check. VPN 5 has valid = 0 — the page is not present. In a real system, this would trigger the kernel's page fault handler (L13). The process would either continue (after loading the page) or be killed (if the access was illegal).

e->accessed = 1

The accessed bit. Every translation sets this bit. The kernel uses the accessed bit (and dirty bit) to implement LRU page replacement (L13's content).

(frame << 12) | offset

Step 3. Shift frame number into high bits, OR in the offset. For VA 0x000017FF: frame 12 (0xC) shifted left 12 = 0xC000. OR with offset 0x7FF = 0xC7FF. Physical address!

The Magic of the Offset

Notice: the offset is never transformed. 0x7FF stays 0x7FF. This is why page and frame sizes must be identical — the offset means the same thing in both spaces.

Lecture 12 — TLB Acceleration & Caching Math

Paging solves fragmentation but doubles memory latency — every access now walks the page table first. For a 3 GHz CPU running normal workloads, this would be catastrophic. The solution is the Translation Lookaside Buffer — an ultra-fast associative cache inside the CPU that remembers recent virtual-to-physical translations. A TLB hit bypasses the page table entirely, reducing access back to a single memory trip.
