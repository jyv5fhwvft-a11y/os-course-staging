🎒 EVERYDAY SIMPLIFIED: THE SAVED-STATE SNAPSHOT

The PCB Metaphor

🎮💾⚡
The Narrative

When you pause a video game and save, the game captures everything: your health, your position, your inventory, your current quest, your timers. When you later load the save, the game resumes as if no time has passed. The PCB is the OS's save-game snapshot for a process — captures registers, program counter, memory mapping, file descriptors — the complete state needed to resume.

Execution Path

During a context switch, the OS saves the current process's state into its PCB and loads a different process's state from its PCB.

Micro-Accessibility Context

Why you can run three hundred processes on one CPU — each is paused, saved, and resumed via its PCB snapshot.

🎒 EVERYDAY SIMPLIFIED: THE FOUR-DRAWER CABINET

The Memory Segments Metaphor

🗄️📁📄
The Narrative

A filing cabinet with four labeled drawers: Top drawer (Text) — immutable instructions, the compiled program. Second drawer (Data) — global variables. Third drawer (Heap) — dynamically allocated memory growing upward. Bottom drawer (Stack) — local variables and function call frames growing downward as calls nest.

Execution Path

Text sits low (protected by permissions). Stack grows down from high addresses. Heap grows up from Data. They expand toward each other — a deliberate collision arrangement.

Micro-Accessibility Context

The map that L11 paging will partition and L24 exploits will violate.

🎒 EVERYDAY SIMPLIFIED: THE BOOKMARK SET

📖🔖📌

A reader at a desk needs several bookmarks: one for the current story page (program counter), one for a stack of notes being scribbled (register values), one for a list of documents currently in use (file descriptors). 🎒 EVERYDAY SIMPLIFIED: THE LEDGER & DRAWING SUITE

The Summary Metaphor

🟢 Paused Process

State frozen in the PCB. Waiting in a queue. Ready to be restored at any moment.

🔵 Running Process

State reflected in live registers and memory. Executing on the CPU right now.

A process oscillates between these two states. The PCB is the bridge between them. Every scheduler decision is a save/restore cycle through the PCB.

Text Segment

Compiled machine instructions. Read-only, executable. Often shared between multiple runs of the same binary.

Data Segment

Global and static variables. Two sub-regions: .data for initialized globals, .bss for zero-initialized.

Heap

Dynamically allocated memory from malloc(), calloc(), new. Grows upward.

Stack

Local variables and function call frames. Grows downward. The stack pointer register tracks the current top.

💻 SYSTEMS COHESION: THE KERNEL LEDGER

The Process Control Block (PCB)

PCB Field Categories

Identification: PID, PPID, UID/GID (owner identity for L22 access control).

State: New, Ready, Running, Blocked, Terminated.

Program Counter: Virtual address of next instruction.

CPU Registers: All general-purpose registers, stack pointer, flags.

Memory Management: Pointer to page table (L11), base/bound info (L10).

File Descriptors: Table of open FDs (L17).

Scheduling: Priority, remaining slice, CPU time used.

Accounting: Total CPU time, start time, exit status.

Signals: Handler table for SIGTERM, SIGINT, etc.

Links: Parent and children PCB pointers.

The Verdict

The PCB is the complete state of the process. Every other subsystem contributes a field to it.

In Linux, the PCB is struct task_struct — a huge structure with hundreds of fields on modern kernels. It holds not just the fields listed left, but also namespaces (L27), cgroup memberships (L27), seccomp filters (L24), credentials (L23), and more.

Every lecture from here on out manipulates this struct.

State Transitions

New → Ready: PCB fully initialized.

Ready → Running: Scheduler picks this process.

Running → Blocked: Process waits on I/O or lock.

Running → Ready: Time slice expires (preemption).

Blocked → Ready: I/O completes or lock releases.

Running → Terminated: exit() called.

The Verdict

Only one thread per physical core can be in the Running state at any instant. The other states allow the system to have hundreds of processes without needing hundreds of cores.

Running → Blocked is what makes I/O-bound workloads efficient — the CPU is freed for others while the blocked process waits.

💻 SYSTEMS COHESION: THE KERNEL'S PROCESS REGISTRY

The Process Table and the task_struct Layout

The Process Table

A doubly-linked list of struct task_struct objects. Each represents one process (or thread).

The current pointer: A per-CPU variable pointing to the currently running process's task_struct. Switching processes = changing current.

The task_struct is large: hundreds of fields on a modern kernel. It holds all PCB categories plus namespaces, cgroups, seccomp filters, credentials.

The Process Tree

Every process has a parent pointer and a children list.

The root of the tree is PID 1 (init/systemd), established at boot in L04.

Every process on the system is a descendant of PID 1. The kernel's process table is a tree, not a flat list.

The process table is the kernel's global index of every active process.

💻 SYSTEMS COHESION: THE PCB IN MOTION

Context Switch and PCB Save/Restore

The Context Switch Pipeline

1. Interrupt/syscall: Current process is interrupted (from L20, L03, or scheduler L07).

2. Save state: Kernel saves all registers into the outgoing process's PCB (rip, rsp, general registers, flags).

3. Scheduler decision: The scheduler picks the next process (L07).

4. Load state: Kernel loads the incoming process's saved registers from its PCB.

5. Resume: CPU returns to the resumed process's saved program counter.

6. Continue: The new process resumes exactly where it left off.

The Cost

A context switch costs microseconds — register saves, TLB flushes (from L12), cache pollution.

Why it matters: Modern schedulers minimize context switches. Round Robin at 1 ms quantum means 1000 context switches per second per CPU core.

The fundamental rhythm of multitasking — but not free.

🔗 SYSTEM PIPELINE: RELIES ON RING BARRIER

Core System Cohesion — Relies On L03 Syscalls & L02 Dual-Mode

Every PCB Operation Is a Syscall

fork(), execve(), wait(), exit(), getpid() — each crosses the Ring 3 → Ring 0 barrier from L02 and is dispatched via the syscall table from L03.

The kernel's response to each of these is to modify or create a PCB inside kernel space.

The Barrier Makes the PCB Trustworthy

Without the dual-mode barrier, a user process could directly manipulate its own PCB — corrupting its own state or impersonating another process.

The Ring 0 boundary is what makes the PCB ledger trustworthy.

🔗 SYSTEM PIPELINE: FEEDS INTO EXECUTION & SCHEDULING

Core System Cohesion — Feeds Into L06 & L07–L08

L06 (fork)

Clones a PCB — copies every field, then diverges the child (new PID, COW address space from L11).

L06 (exec)

Overwrites specific PCB fields (new text/data, reset PC) while preserving identity (PID, owner, FDs).

L07–L08 (Scheduler)

🔍 COMPREHENSIVE CRITIQUE: PROCESS TRACKING STRATEGIES

PCB Strategies Across the Five Paradigms

Monolithic PCB

Single global task_struct layout, allocated from kernel slab allocators. Every field is set at creation and updated by kernel code paths. Fast, uniform, but inflexible — adding new process fields requires kernel-wide changes.

Microkernel PCB

Process state is split between kernel (minimal — small thread control block with register state and address-space reference) and user-space servers (richer per-process state). The kernel maintains only what is required for isolation and scheduling.

Layered PCB

Structured in layers — hardware register save area at bottom, scheduler metrics above, memory references above, security credentials at top. Each layer evolves independently; the compiler enforces layering through struct composition.

Modular PCB

The kernel's task_struct layout is fixed, but LSM hooks allow security metadata to be attached via specialized modules — the process holds a per-module blob pointer. Extensibility without kernel recompilation.

Hybrid PCB

Core scheduling fields in-kernel for hot-path performance; security context (namespace pointers, cgroup membership, seccomp filters) in dedicated structures referenced from the PCB. Modern Linux is functionally hybrid.

🏷️ SYSTEM LEXICON: MASTERING THE PROCESS VOCABULARY

Base Process Terms

Term 01 · Process

An active instance of a running software application containing its own dedicated execution context and address boundaries; unlike a static program binary, a process has runtime state — registers, memory, file descriptors, program counter — tracked by a kernel PCB.

(A business actively operating in the shared office building, with its own ledger folder.)

Term 02 · Process Control Block (PCB)

The definitive kernel data structure used to track, schedule, and preserve a process's metadata — including PID, process state, program counter, CPU registers, memory management information, file descriptor table, and scheduling metrics. It is the complete snapshot of a process's state at any moment.

(The accountant's ledger — the complete saved-state file for one business.)

🏷️ SYSTEM LEXICON: MASTERING THE PROCESS VOCABULARY

Advanced Process Terms

Term 03 · Program Counter (PC)

A specialized physical CPU register that stores the memory address of the next instruction waiting to be executed; saved into the PCB on context switch and restored on resumption. On x86-64, this is the RIP register.

(The bookmark that tells the reader exactly where to resume.)

Term 04 · Process States

The operational lifecycle flag of a task — one of New, Ready, Running, Blocked/Waiting, or Terminated — tracked in the PCB's state field; transitions between states are triggered by syscalls, scheduler decisions, and I/O events.

(The traffic light of process progress — waiting, running, blocked, done.)

Term 05 · Context Switch

The physical hardware/software process of saving the active CPU register state into the outgoing process's PCB and restoring a different task's context from its PCB; the CPU then resumes executing the new process exactly where it was last paused.

(The pause-and-resume rhythm that lets hundreds of programs share one CPU.)

💻 CODE DISSECTION: C PCB INSPECTION PANEL

Inspecting a Process's PCB from User Space

// Inspecting a running process's PCB-visible state from user space
// On Linux, /proc/self/ exposes the kernel's task_struct to user space
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

void inspect_self_process() {
    pid_t pid = getpid();
    pid_t ppid = getppid();
    char path[128], buffer[1024];
    FILE* f;

    printf("=== Process PCB Inspection (PID %d) ===\n\n", pid);

    // --- Identity fields ---
    printf("[IDENTITY]\n");
    printf("  PID:     %d\n", pid);
    printf("  PPID:    %d\n", ppid);
    printf("  UID:     %d\n", getuid());
    printf("  GID:     %d\n", getgid());
    printf("  Session: %d\n", getsid(0));
    printf("  PGRP:    %d\n", getpgrp());

    // --- Process state from /proc/self/stat ---
    printf("\n[STATE]\n");
    f = fopen("/proc/self/stat", "r");
    if (f) {
        char comm[64], state;
        int ppid_v, pgrp_v, session_v;
        unsigned long minflt, cminflt, majflt, cmajflt;
        long cutoff, priority, nice;
        int num_threads;
        fscanf(f, "%d %s %c %d %d %d %lu %lu %lu %lu %ld %ld %ld %d",
               &pid, comm, &state, &ppid_v, &pgrp_v, &session_v,
               &minflt, &cminflt, &majflt, &cmajflt,
               &cutoff, &priority, &nice, &num_threads);
        fclose(f);
        printf("  State:     %c (%s)\n", state,
               state == 'R' ? "Running" :
               state == 'S' ? "Sleeping/Blocked" :
               state == 'T' ? "Stopped" : "Other");
        printf("  Threads:   %d\n", num_threads);
        printf("  Priority:  %ld\n", priority);
    }

    // --- Memory segments from /proc/self/maps ---
    printf("\n[MEMORY SEGMENTS (from /proc/self/maps)]\n");
    f = fopen("/proc/self/maps", "r");
    if (f) {
        int line_count = 0;
        while (fgets(buffer, sizeof(buffer), f) && line_count < 8) {
            buffer[strcspn(buffer, "\n")] = 0;
            printf("  %s\n", buffer);
            line_count++;
        }
        fclose(f);
    }

    // --- Open file descriptors ---
    printf("\n[FILE DESCRIPTORS]\n");
    snprintf(path, sizeof(path), "/proc/self/fd");
    char cmd[160];
    snprintf(cmd, sizeof(cmd), "ls -la %s 2>/dev/null | head -6", path);
    system(cmd);
}

int main() {
    inspect_self_process();
    return 0;
}

Use code with caution.

💻 CODE DISSECTION: TRACING PCB FIELDS

Walking the PCB Inspection Trace

getpid() · getppid() · getuid() · getgid()

Direct syscalls reading PCB identity fields. getpid() reads current->pid — a single field access on the running task_struct.

fopen("/proc/self/stat")

Opens a virtual file (a /proc node from L17) that exposes raw task_struct fields as text. The kernel synthesizes it on read — no disk involved.

fscanf parsing state

Reads pid, comm (executable name), state (R/S/T/Z), ppid, pgrp, session, minor/major page faults, priority, nice, num_threads — directly from the PCB.

fopen("/proc/self/maps")

Lists memory mappings — the Text, Data, Heap, Stack, and shared library segments from L05's memory layout. Each line shows start, end, permissions, and file backing.

ls /proc/self/fd

Lists open FDs as symlinks to their targets. This is the FD table from L17, exposed to user space.

The /proc filesystem

A kernel-synthesized virtual filesystem where the kernel exposes PCB fields, memory maps, and FD tables as readable files. The primary way tools like ps, top, htop inspect process state.

The Big Question

What happens if Heap-growing-up collides with Stack-growing-down? Answer: the process has run out of memory — the fundamental virtual memory ceiling L13 will solve via demand paging and swap.

🏆 RETROSPECTIVE: SYLLABUS DISSECTION SUMMARY

Grand Lecture Summary

01

A process is a running program with its own address space, organized into four segments — Text (instructions), Data (globals), Heap (dynamic allocations growing up), and Stack (local variables growing down). The layout is enforced by the ELF format, the compiler, and the kernel's loader.

02

The Process Control Block is the kernel's complete ledger for a process — PID, state, program counter, all CPU registers, page table pointer, FD table, scheduling metrics, signal handlers, and parent/child links. Without it, no process could be paused and resumed.

03

A context switch is the save-restore cycle through the PCB: save the current process's register state, load the next process's register state, resume execution exactly where the next process left off. It is the fundamental rhythm of multitasking — not free, but the foundation of modern OS behavior.
