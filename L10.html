The Core Objective

Manually derive valid physical memory address locations from logical addresses given specific Base and Bound hardware register limits, and catch security bounds exceptions.

The Problem Hook: Every program is compiled as if it owns the entire machine's memory — starting from address zero and going up to whatever size it needs. But in a multiprogrammed system, five programs are running simultaneously, all convinced they start at address zero. If each actually wrote to physical address zero, they would obliterate each other. How does the hardware trick five programs into sharing one RAM chip, each believing it owns the whole thing?

🎒 EVERYDAY SIMPLIFIED: THE HOTEL ROOM NUMBERING ILLUSION

The Relocation Metaphor

🏨🔑🚪
The Narrative

Every guest at a hotel resort receives an automated room booklet saying they are in "Room 100" (the logical address). When they go to find their room, they use a master keycard lock. The hotel's physical architecture silently maps each guest's "Room 100" to a completely different floor. Guest A's "Room 100" is really room 500. Guest B's "Room 100" is really room 800. They both think they occupy room 100, but the front desk relocates them seamlessly.

Execution Path

Base register holds the physical starting offset. Guest's logical 100 + base 500 = physical 600.

Micro-Accessibility Context

Every guest (program) believes the same illusion, but the OS silently provides a different physical location.

🎒 EVERYDAY SIMPLIFIED: THE HOTEL KEYCARD BOUND

The Bound Check Metaphor

🛡️🚫🚪
The Narrative

The hotel also tells Guest A their room is a small 10-room suite (the bound). If Guest A tries to open "Room 115" (logical address 15, past their bound of 10), the keycard fails instantly. The door is not just locked — the system actively rejects the attempt and sounds a security alert.

Execution Path

The Bound register holds the maximum allowable offset. If the logical address is < 0 or >= bound, the CPU raises a bounds exception.

Micro-Accessibility Context

The bound is what prevents Guest A from wandering into Guest B's suite. It is the security mechanism.

🎒 EVERYDAY SIMPLIFIED: THE OFFICE CUBICLE SHARING

The Multiprogramming Metaphor

🏢👥🔄
The Narrative

An office building has one large open floor. Different teams (processes) are placed in non-overlapping cubicle blocks. Team A gets cubicles 0–49, Team B gets cubicles 50–99, Team C gets cubicles 100–149. Each team's internal numbering starts at 0 (their "desk 0", "desk 1" — the logical addresses), but their physical cubicle numbers are their block offset plus their internal index.

Execution Path

Each process is loaded at a different physical base in RAM. The OS gives each process a different base register pointing to its block.

Micro-Accessibility Context

Contiguous allocation of each process's address space — the first approximation of memory virtualization.

🎒 EVERYDAY SIMPLIFIED: THE SWISS CHEESE

The Fragmentation Metaphor

🧀🕳️📊
The Narrative

The office building is now riddled with holes. A team of 20 cubicles left, freeing cubicles 20–39. A new team of 15 arrives, fits in 20–34. Then a team of 10 arrives — they need 10 cubicles, but the only free space is cubicles 35–39 (only 5 cubicles) plus 15 more scattered cubicles elsewhere. Total free space exists (say 40 cubicles total), but no single contiguous block is large enough for the new team. This is external fragmentation — the memory exists, but it is scattered.

Execution Path

Base-and-bound requires contiguous physical blocks. When processes finish and new ones arrive, the memory becomes fragmented.

Micro-Accessibility Context

Fragmentation is the fatal flaw of base-and-bound. L11's paging will solve it.

🎒 EVERYDAY SIMPLIFIED: THE RELOCATION SUITE

The Summary Metaphor

✅ What Base-and-Bound Provides

Relocation (each process sees address 0), isolation (bounds prevent overlap), and fast lookup (one addition + one comparison).

❌ What It Fails At

Requires contiguous physical blocks. Large free space totals become useless when fragmented. Cannot support virtual memory larger than physical RAM.

Base-and-bound is the first approximation. It works for batch systems with small processes but collapses under multitasking workloads. Its failures motivate paging.

💻 SYSTEMS COHESION: THE LOGICAL VS PHYSICAL DISTINCTION

Logical Address vs Physical Address

Logical Address (Virtual)

An address generated by the compiler and CPU instruction stream during development and runtime execution.

Also called: virtual address, program address, process address.

Property: Always starts at 0 for each process. The program thinks it owns all memory.

Example: The assembly instruction mov 0x100, %rax — reads from logical address 0x100 (256).

Physical Address

The actual, hardware-wired slot location inside the physical RAM chip matrix.

Also called: real address, actual RAM address.

Property: Shared globally among all running processes. Each byte of RAM has exactly one physical address.

Example: RAM chip slot 0x1400 (5120) — some specific physical byte location.

The core abstraction: The base register silently translates logical addresses into physical addresses at runtime, invisible to the process.
💻 SYSTEMS COHESION: THE HARDWARE ARBITRATION TRIAD

Base and Bound Registers

Base Register

A physical CPU tracking register that stores the absolute starting physical address of a program's active memory slot.

Set by the OS on context switch. Read by the MMU on every address access.

Example: Base = 14000 means the process's logical address 0 maps to physical address 14000.

Bound Register

A physical hardware safety register tracking the maximum size allocation block granted to a running process context.

Set by the OS on context switch. Read by the MMU on every address access.

Example: Bound = 2000 means logical addresses 0–1999 are valid; 2000+ triggers a bounds exception.

The MMU

The Memory Management Unit — hardware inside the CPU that performs the translation and bounds check on every memory access.

Per-access work: One addition (logical + base) and one comparison (logical < bound).

Extremely fast — hardware circuits perform this in a single clock cycle.

💻 SYSTEMS COHESION: THE ADDRESS TRANSLATION FORMULA

The Translation Mechanism

The Translation Rule

Every memory access follows this exact hardware sequence:

1. Check: if (logical_addr < 0) OR (logical_addr >= Bound) → FAULT

2. Translate: physical_addr = logical_addr + Base

3. Access: Read or write to physical_addr

If the check fails, the CPU raises a segmentation fault before the memory access occurs. The kernel's trap handler (L03) catches the exception and typically terminates the process.

✅ Valid Translation Example

Process configuration: Base = 14000, Bound = 2000.

Logical address: 450.

Check: 450 < 2000 ✓ (passes bounds check).

Translate: 450 + 14000 = 14450.

Result: Physical address 14450. Valid execution.

❌ Failed Translation Example

Process configuration: Base = 14000, Bound = 2000.

Logical address: 2100.

Check: 2100 ≥ 2000 ✗ (exceeds bound!).

Result: Hardware triggers a CPU exception trap.

The process is terminated with a Segmentation Fault.

💻 SYSTEMS COHESION: THE FATAL FLAW

External Fragmentation

The Problem

Base-and-bound requires contiguous physical blocks. When processes finish and new ones arrive, the memory becomes full of small "holes" between allocations.

A new process needs 8 KB. Total free space is 20 KB — but scattered across 5 fragments of 4 KB each. No single fragment is large enough.

This is called external fragmentation — the memory exists, but not where it is needed.

The Mitigation (and Why It Fails)

Compaction: Shift all occupied blocks together, combining holes into one large block. Works but requires copying every process in memory — extremely slow.

Allocation policies: First-fit, best-fit, worst-fit. Reduce but do not eliminate fragmentation.

Compaction only works if all processes can be moved — which requires virtual memory, which base-and-bound cannot provide.

The Verdict: Base-and-bound's fixed-size contiguous allocation is fundamentally incompatible with long-running multiprogramming systems. Its failures drive the invention of paging (L11).
🔗 SYSTEM PIPELINE: RELIES ON DUAL-MODE BARRIER

Core System Cohesion — Relies On L02

The Base/Bound Registers Are Privileged

Only Ring 0 code (the kernel) can read or modify the base and bound registers. If user code could write them, it could set its own base to cover the entire RAM chip and read other processes' memory.

The Dual-Mode Barrier Protects the Registers

When the CPU executes a context switch (L06), the kernel writes new base/bound values into the registers. In Ring 3, those writes would trigger a #GP fault.

The Bounds Check Is Enforced Every Access

The MMU checks the bound on every memory access — but the check relies on the bound register holding its correct value, which relies on the hardware privilege barrier from L02.

Removing the Barrier Collapses the System

If user code could modify the bound register, it could break out of its memory sandbox and access any process's memory. The base/bound scheme is only as secure as the dual-mode barrier.

🔗 SYSTEM PIPELINE: FEEDS INTO PAGING AND BEYOND

Core System Cohesion — Feeds Into L11 & L13

L11 (Paging)

Paging fixes base-and-bound's fatal flaw: it splits memory into small fixed-size frames, eliminating external fragmentation entirely. Each process's pages can be scattered anywhere in physical RAM — no contiguity requirement.

L12 (TLB)

Paging introduces the page table, which requires walking on every access. The TLB caches recent translations to hide this cost — the base-and-bound single-addition becomes a cached-TLB hit.

L13 (Demand Paging)

Once paging is in place, the OS can defer loading pages until they are actually accessed. Virtual memory larger than RAM becomes possible — impossible with base-and-bound.

The Iteration

Base-and-bound → paging → TLB → demand paging → swap. Each layer fixes the previous layer's weakness. This is the entire arc of Module 3.

🔍 COMPREHENSIVE CRITIQUE: MEMORY MODEL STRATEGIES

Relocation Strategies Across the Five Paradigms

Monolithic Relocation

Base/bound hardware registers managed directly by the kernel's memory manager. Fastest (hardware-level check) but inflexible — the kernel must track all memory allocations and fragmentation manually.

Microkernel Relocation

The kernel maintains only a minimal address space descriptor (base, bound, or an equivalent capability). User-space memory managers enforce higher-level policies. Slower, but the isolation is provable — base/bound is a kernel primitive, not a policy.

Layered Relocation

Hardware MMU performs the check → kernel maintains page tables → user-space memory allocator manages its own heap. Each layer adds policy but never bypasses the hardware bound check.

Modular Relocation

The kernel's memory manager is modular — different MMU configurations (base/bound, paging, segmentation) loaded per hardware platform. Modern Linux uses paging exclusively but supports segmentation via modules.

Hybrid Relocation

Base/bound for simple embedded devices, paging for general-purpose systems, segmentation + paging for x86 legacy compatibility. Modern OSes offer multiple memory models based on workload.

🏷️ SYSTEM LEXICON: MASTERING THE RELOCATION VOCABULARY

Base Relocation Terms

Term 01 · Logical Address

A virtual address generated by the compiler and CPU instruction stream during development and runtime execution. It starts at address 0 for every process and represents the process's internal view of memory. Also called a virtual address.

(The hotel guest's assigned "Room 100" — the address they think they have.)

Term 02 · Physical Address

The actual, hardware-wired slot location inside the physical RAM chip matrix. It is shared globally among all processes, and each byte of RAM has exactly one physical address. Also called a real address.

(The real room number — what the hotel manager actually knows.)

🏷️ SYSTEM LEXICON: MASTERING THE RELOCATION VOCABULARY

Advanced Relocation Terms

Term 03 · Base Register

A physical CPU tracking chip that stores the absolute starting physical address of a program's active memory slot. Set by the kernel on context switch, read by the MMU on every memory access. Every logical address is offset by the base to produce the physical address.

(The front desk's mapping from "Room 100" to the guest's real floor.)

Term 04 · Bound Register

A physical hardware safety register tracking the maximum size allocation block granted to a running process context. If any logical address exceeds the bound, the CPU raises a segmentation fault before the memory access occurs — the security mechanism that prevents a process from reading or writing outside its allocated region.

(The hotel keycard that fails when a guest tries "Room 115" past their 10-room bound.)

Term 05 · External Fragmentation

A memory management problem where total free space is sufficient for a new allocation, but no single contiguous block is large enough because free space is scattered across small holes between existing allocations. The fatal flaw of contiguous allocation schemes like base-and-bound.

(The Swiss cheese — plenty of cheese total, but no single solid slice large enough.)

💻 CODE DISSECTION: C BASE-AND-BOUND SIMULATOR

Simulating the MMU Translation

// Simulating base-and-bound MMU address translation in C
// Demonstrates valid access, bounds violation, and multi-process isolation
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int pid;
    unsigned int base;
    unsigned int bound;
} ProcessRegisters;

// The MMU translation function — runs on every memory access
int mmu_translate(ProcessRegisters* proc, unsigned int logical_addr,
                   unsigned int* physical_out) {
    // 1. Bounds check
    if (logical_addr >= proc->bound) {
        printf("  [PID %d] FAULT: logical 0x%X exceeds bound 0x%X\n",
               proc->pid, logical_addr, proc->bound);
        return -1;  // Segmentation fault
    }

    // 2. Translate
    *physical_out = logical_addr + proc->base;
    printf("  [PID %d] logical 0x%X -> physical 0x%X\n",
           proc->pid, logical_addr, *physical_out);
    return 0;
}

int main() {
    // Three processes, each with its own base and bound
    ProcessRegisters processes[] = {
        { .pid = 1001, .base = 0x0000, .bound = 0x2000 },  // 0-8KB
        { .pid = 1002, .base = 0x2000, .bound = 0x2000 },  // 8-16KB
        { .pid = 1003, .base = 0x4800, .bound = 0x0800 },  // 18-20KB
    };

    printf("=== Base-and-Bound MMU Translation ===\n\n");

    // Test cases: (process_index, logical_address)
    struct { int p; unsigned int la; } tests[] = {
        { 0, 0x0100 },  // Process 1, address 0x100 → valid
        { 0, 0x1FFF },  // Process 1, address 0x1FFF (just below bound) → valid
        { 0, 0x2000 },  // Process 1, address 0x2000 (at bound) → FAULT
        { 1, 0x0040 },  // Process 2, address 0x40 → valid
        { 1, 0x1F00 },  // Process 2, address 0x1F00 → valid
        { 2, 0x0400 },  // Process 3, address 0x400 → valid
        { 2, 0x0800 },  // Process 3, address 0x800 (at bound) → FAULT
    };

    for (int i = 0; i < 7; i++) {
        unsigned int physical;
        int result = mmu_translate(&processes[tests[i].p],
                                       tests[i].la, &physical);
        if (result != 0) {
            printf("  [PID %d] → SIGSEGV: process would be terminated\n\n",
                   processes[tests[i].p].pid);
        }
    }

    printf("\n=== Isolation Demonstration ===\n");
    printf("Each process sees its OWN logical address 0x0100:\n");
    unsigned int phys;
    for (int i = 0; i < 3; i++) {
        mmu_translate(&processes[i], 0x0100, &phys);
    }
    printf("Same logical address, three DIFFERENT physical addresses!\n");
    printf("This is base-and-bound isolation.\n");

    return 0;
}

Use code with caution.

💻 CODE DISSECTION: TRACING THE MMU TRANSLATION

Walking the Base-and-Bound Trace

mmu_translate(proc, logical, &physical)

The core MMU function. In real hardware, this is a single-cycle logic circuit. In our C simulation, it is a few operations that exactly mirror the hardware behavior.

if (logical >= proc->bound)

The bounds check. If the logical address equals or exceeds the bound, the memory access is rejected before it happens. In real hardware, this triggers a #GP fault. In the OS, the kernel catches the fault and terminates the offending process.

*physical_out = logical + base

The translation. A single addition. This is why base-and-bound is extremely fast — one hardware adder per memory access. In contrast, paging (L11) requires a page table walk unless the TLB (L12) has a cached translation.

The Isolation Demo

All three processes access logical address 0x0100. They get three different physical addresses (0x0100, 0x2100, 0x4900). Each process believes it has "address 0x0100" — but each is actually pointing to a different byte in the shared RAM chip.

Test case 0x2000 → FAULT

Process 1 attempts to access address 0x2000, which is exactly at its bound. The MMU rejects the access, and the process would be terminated with SIGSEGV. This is the same failure mode as a real NULL pointer dereference or buffer overflow.

The Seamless Illusion

The entire demonstration shows that each process sees its own isolated address space starting from 0. This is the entire point of base-and-bound: it makes the multiprogramming illusion possible.

🏆 RETROSPECTIVE: SYLLABUS DISSECTION SUMMARY

Grand Lecture Summary

01

Base-and-bound is the first form of memory virtualization. Each process has a base register (its physical starting address) and a bound register (its maximum size). The MMU adds base to every logical address and checks against the bound.

02

The scheme provides relocation and isolation: each process sees address 0, and the bounds check prevents overlap. But it requires contiguous physical blocks, which leads to external fragmentation — free memory scattered across small holes that cannot satisfy large allocations.

03

Base-and-bound is fast (one addition, one comparison per access) but fundamentally limited. It cannot support processes larger than physical RAM, cannot support virtual memory, and cannot eliminate fragmentation. Its failures motivate L11's paging — the solution that all modern operating systems use.

Lecture 11 — The Paging Model & Fixed-Size Translation Matrix

Base-and-bound is fast but fatally fragmented. The fix is dramatic: chop memory into tiny fixed-size units called pages (virtual) and frames (physical), then map them through a page table. Any page can go into any frame — no contiguity required. External fragmentation disappears. But a new cost appears: every memory access now requires two trips to RAM (one for the page table, one for the data).
