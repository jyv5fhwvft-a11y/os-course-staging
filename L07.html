The Core Objective

Manually compute turn-around time, response time, and average wait metrics for a given array of task vectors under FCFS, SJF, and Round Robin scheduling algorithms.

The Problem Hook: A CPU core can execute exactly one instruction stream at a time. But a modern system has three hundred processes queued and waiting for that one core. Which process gets to run right now? The kernel scheduler makes this decision thousands of times per second. Pick wrong — and the whole system collapses into a sluggish mess. Pick right — and users never notice. What are the foundational algorithms that make this choice?

🎒 EVERYDAY SIMPLIFIED: THE GROCERY STORE LINE

The FCFS Metaphor

🛒👥💳
The Narrative

A grocery store has one cashier. Customers join a single line based on arrival time. The first customer has a massive cart — 200 items. The second customer has a single pack of gum. The cashier services the cart first, taking 8 minutes; the gum buyer waits 8 minutes for what could have been 15 seconds. Nobody cuts the line, and the small task is trapped behind the large one.

Execution Path

FCFS runs processes in arrival order. Perfectly fair in a legal sense, catastrophically unfair in a waiting time sense.

Micro-Accessibility Context

This is the "convoy effect" — a small task trapped behind a large one — the classic FCFS flaw.

🎒 EVERYDAY SIMPLIFIED: THE EXPRESS CHECKOUT

The SJF Metaphor

⚡🛒💰
The Narrative

The store manager, frustrated by the convoy effect, reorders the line: "Smallest cart first, please." The gum buyer is now served in 15 seconds; the medium cart in 2 minutes; the massive cart finally gets its 8 minutes — but after everyone else. Average waiting time plummets.

Execution Path

SJF runs processes with the shortest burst time first. It dramatically minimizes average waiting time — the mathematically provable optimum. But it must know burst times in advance, which is impossible.

Micro-Accessibility Context

SJF is the theoretical optimum for average wait time — and the practical impossibility at the same time.

🎒 EVERYDAY SIMPLIFIED: THE TIMED TELLER

The Round Robin Metaphor

⏱️🔄👥
The Narrative

The store installs a rule: each customer gets exactly 30 seconds at the cashier. If their transaction is not finished, they are sent to the back of the line, and the next customer gets their 30 seconds. Everyone gets a turn; nobody starves; responsiveness is excellent — but the total time to finish a big cart is much longer.

Execution Path

Round Robin allocates a fixed time quantum to each process. When the quantum expires, the process is preempted and placed back in the queue.

Micro-Accessibility Context

RR is the foundational preemptive algorithm — the first to give every process a guaranteed slice of CPU.

🎒 EVERYDAY SIMPLIFIED: THE REFEREE'S WHISTLE

The Preemption Metaphor

📣⚡🛑
The Narrative

Even after a process starts running, the OS can interrupt it — via a hardware timer signal, or an I/O event requiring immediate attention. This is preemption. The process is not asked to yield; it is forced to pause, its state saved into its PCB, so another process can run.

Execution Path

Preemption is a hardware-enabled capability — without the timer interrupt, the OS could not forcibly preempt a running user process.

Micro-Accessibility Context

Preemption is the boundary between traditional batch computing and modern interactive multitasking.

🎒 EVERYDAY SIMPLIFIED: THE METRICS SUITE

The Summary Metaphor

🟡 Small Jobs Starved

FCFS optimizes simplicity but suffers convoy effect. Small tasks wait behind large ones.

🟢 Balanced Response

RR minimizes response time but increases total turnaround due to overhead. Everyone gets a turn.

Different algorithms optimize different metrics — no algorithm wins all of them. The right choice depends on workload characteristics.

💻 SYSTEMS COHESION: THE MEASUREMENT TOOLKIT

Scheduling Metrics and Gantt Charts

The Four Core Metrics

Arrival Time (AT): When the process enters the ready queue.

Burst Time (BT): How much CPU time the process will need.

Completion Time (CT): When the process finishes execution.

Wait Time (WT): Total time in the ready queue. WT = CT − AT − BT.

Turnaround Time (TAT): Total time from arrival to completion. TAT = CT − AT = WT + BT.

Response Time (RT): Time from arrival to first CPU allocation. Critical for interactive systems.

Gantt Chart Convention

Time runs left to right; each process occupies a horizontal slice showing when it runs.

A Gantt chart makes waiting, running, and preemption visible at a glance.

These metrics measure different things. SJF minimizes average wait time; RR minimizes response time; FCFS maximizes wait-time variance.

💻 SYSTEMS COHESION: THE SIMPLE FIFO QUEUE

First-Come-First-Served (FCFS)

The Algorithm

Data structure: A simple FIFO queue.

Policy: When CPU is free, dispatch the oldest process.

Preemption: None. Runs until complete or blocks.

Complexity: O(1) enqueue, O(1) dequeue.

The Convoy Effect

Small processes trapped behind long ones.

Average wait time skyrockets when a giant process arrives first.

FCFS = maximally unfair to short jobs.

💻 SYSTEMS COHESION: THE OPTIMAL WAIT-TIME ALGORITHM

Shortest-Job-First (SJF)

The Algorithm

Data structure: A priority queue ordered by burst time.

Policy: Dispatch the process with the smallest burst time.

Preemption: None (basic version). Preemptive variant is SRTF.

Complexity: O(log n) to maintain the priority queue.

The Fatal Flaw

Mathematically optimal for average wait time — proven.

But requires knowing burst times in advance — impossible.

Real schedulers approximate SJF by predicting next burst from past bursts (exponential averaging).

💻 SYSTEMS COHESION: THE TIMED-SLICE FAIRNESS

Round Robin (RR)

The Algorithm

Data structure: A FIFO queue of ready processes.

Policy: Each process gets up to Q of CPU time. If not finished, preempt and requeue at the back.

Preemption: Yes — via the timer interrupt. The key difference from FCFS.

Quantum choice: Small Q = responsiveness; large Q → FCFS behavior. Typical: 10–100 ms.

Why RR Wins

Every process gets a CPU turn within Q ms of arrival.

Users perceive interactive responses as instant if Q < 100 ms.

RR = maximum responsiveness at the cost of slightly higher average wait.

💻 SYSTEMS COHESION: THE CONTEXT SWITCH TAX

The Preemption Overhead Trade-off

Small Q (e.g., 1 ms)

Pros: Excellent responsiveness. Users feel instant interactions.

Cons: 100 processes → ~100 context switches/second. At 5μs per switch → 0.5% CPU overhead just switching. At 1000 processes, this becomes 5%.

Large Q (e.g., 100 ms)

Pros: Fewer switches, minimal overhead.

Cons: Interactive response degrades. A user typing a keystroke may wait 100 ms to see it — exceeding the human perception threshold.

The Rule of Thumb: The time quantum should be much larger than the context switch cost, but much smaller than the human interaction latency. Typical: Q ≈ 10–100 ms, context switch ≈ 5–10 μs. This gives less than 0.1% switch overhead while keeping response time under 100 ms.
🔗 SYSTEM PIPELINE: RELIES ON PROCESS AND SWITCH INFRASTRUCTURE

Core System Cohesion — Relies On L05 & L06

L05 (PCB) — FCFS

Reads arrival_time from PCB, enqueues in FIFO, dispatches oldest. Runs to completion — no preemption.

L05 (PCB) — SJF

Reads burst_time (or an estimate) from PCB, uses priority queue, dispatches smallest.

L05 (PCB) + L06 (Context Switch) — RR

Reads arrival_time, dispatches in FIFO order, uses a timer interrupt to preempt after Q expires, then saves/restores PCB registers.

The Architectural Bond

Without L05's PCB, no scheduling decision could be persisted. Without L06's context switch, no scheduling decision could be executed. L07 is a decision layer above L05/L06's mechanism.

🔗 SYSTEM PIPELINE: FEEDS INTO MLFQ AND THREADS

Core System Cohesion — Feeds Into L08 & L09

L08 (MLFQ)

Combines multiple priority queues with feedback — a task that uses its full quantum is downgraded; a task that yields early is upgraded. Inherits RR's preemption mechanism and adapts it dynamically.

L09 (Threads)

Applies the same scheduling algorithms at the thread level — a process with 8 threads gets 8 independent entries in the scheduler's ready queue.

Architectural Bond: L07 introduces the foundational algorithms — FCFS, SJF, RR. But real systems need something more sophisticated. L08 will combine them into an adaptive policy; L09 will apply them at the thread level.
🔍 COMPREHENSIVE CRITIQUE: KERNEL SCHEDULER ARCHITECTURES

Scheduling Strategies Across the Five Paradigms

Monolithic Scheduler

The scheduler is a single in-kernel function (schedule() in Linux) called on every context switch. All scheduling logic lives in Ring 0, operating on the global run queue. Fastest, but any scheduler bug affects the entire system.

Microkernel Scheduler

The scheduler itself is a user-space server. The kernel exposes a minimal "yield" and "wake" primitive; the scheduler decides who runs next. Much slower (IPC on every decision), but the scheduler is fully isolated and swappable.

Layered Scheduler

Strict layering — run queue management → policy selection → dispatch. Each layer is inspectable and testable in isolation. Enables policy plug-ins that swap the algorithm without touching queue management.

Modular Scheduler

The kernel's scheduler is a pluggable module (Linux's sched_ext framework, added in 6.12). Scheduling algorithms (FIFO, RR, EEVDF, custom) are loadable at runtime.

Hybrid Scheduler

The kernel has multiple scheduling classes — real-time (SCHED_FIFO, SCHED_RR), fair (SCHED_NORMAL), and idle (SCHED_IDLE) — each with its own algorithm. This is the actual modern Linux model.

🏷️ SYSTEM LEXICON: MASTERING THE SCHEDULING VOCABULARY

Base Scheduling Terms

Term 01 · Preemption

The ability of an operating system to forcefully pause a running process and hand the CPU core to a different task. Enabled by the hardware timer interrupt which fires periodically and returns execution to the kernel's scheduling logic. Preemptive scheduling algorithms can interrupt at any time; non-preemptive let processes run to completion.

(The referee's whistle — forcibly pausing a runner to rotate in another.)

Term 02 · Time Quantum

The maximum continuous block of time a thread is permitted to run under a preemptive scheduling policy before being context-switched. Chosen to balance responsiveness (smaller Q = better) against context-switch overhead (larger Q = fewer switches).

(The 30-second timer per customer in the grocery line.)

🏷️ SYSTEM LEXICON: MASTERING THE SCHEDULING VOCABULARY

Advanced Scheduling Terms

Term 03 · Convoy Effect

A system slowdown scenario where short processes wait a prolonged duration for a long, heavy process to vacate the CPU core; the short jobs "pile up behind" the long job, dramatically increasing average wait time. FCFS suffers from it; SJF eliminates it; RR mitigates it.

(The small gum purchase trapped behind a giant 200-item cart.)

Term 04 · Average Wait Time

The arithmetic mean of the total time processes spent sitting inside the READY queue waiting for execution access. WaitTime = CompletionTime − ArrivalTime − BurstTime; averaged over all processes, it is the primary metric for comparing scheduling algorithms.

(The average time customers spend waiting in line before being served.)

Term 05 · Turnaround Time

The total time from a process's arrival in the system to its completion — TurnaroundTime = WaitTime + BurstTime. It measures the total customer experience — how long the entire task takes from start to finish, including both waiting and executing.

(The total time from when you enter the store to when you leave with your purchase.)

💻 CODE DISSECTION: C SCHEDULER SIMULATOR

FCFS and Round Robin in C

// Simulating FCFS and Round Robin CPU scheduling in C
#include <stdio.h>

typedef struct {
    int pid, arrival, burst, remaining;
    int completion, waiting, turnaround;
} Process;

// ---------- FCFS (non-preemptive) ----------
void fcfs(Process procs[], int n) {
    int time = 0;
    double total_wait = 0, total_tat = 0;

    printf("=== FCFS Scheduling ===\n");
    printf("PID  Arrival  Burst  Start  Complete  Wait  TAT\n");

    for (int i = 0; i < n; i++) {
        if (time < procs[i].arrival) time = procs[i].arrival;
        int start = time;
        time += procs[i].burst;
        procs[i].completion = time;
        procs[i].turnaround = procs[i].completion - procs[i].arrival;
        procs[i].waiting = procs[i].turnaround - procs[i].burst;
        total_wait += procs[i].waiting;
        total_tat += procs[i].turnaround;

        printf("P%d   %2d      %2d     %2d      %2d      %2d    %2d\n",
               procs[i].pid, procs[i].arrival, procs[i].burst,
               start, procs[i].completion,
               procs[i].waiting, procs[i].turnaround);
    }
    printf("Average Wait: %.2f  Average TAT: %.2f\n\n",
           total_wait / n, total_tat / n);
}

// ---------- Round Robin (preemptive, quantum Q) ----------
void round_robin(Process procs[], int n, int Q) {
    int time = 0, completed = 0;
    double total_wait = 0, total_tat = 0;

    for (int i = 0; i < n; i++) procs[i].remaining = procs[i].burst;

    printf("=== Round Robin Scheduling (Q=%d) ===\n", Q);

    while (completed < n) {
        int idle = 1;
        for (int i = 0; i < n; i++) {
            if (procs[i].remaining > 0 && procs[i].arrival <= time) {
                idle = 0;
                int run_time = procs[i].remaining < Q ? procs[i].remaining : Q;
                procs[i].remaining -= run_time;
                time += run_time;
                printf("  [t=%d] P%d runs for %d ms (remaining=%d)\n",
                       time - run_time, procs[i].pid, run_time, procs[i].remaining);

                if (procs[i].remaining == 0) {
                    procs[i].completion = time;
                    procs[i].turnaround = procs[i].completion - procs[i].arrival;
                    procs[i].waiting = procs[i].turnaround - procs[i].burst;
                    total_wait += procs[i].waiting;
                    total_tat += procs[i].turnaround;
                    completed++;
                }
            }
        }
        if (idle) time++;
    }
    printf("Average Wait: %.2f  Average TAT: %.2f\n\n",
           total_wait / n, total_tat / n);
}

int main() {
    Process fcfs_procs[] = {
        { 1, 0, 24, 0, 0, 0, 0 },
        { 2, 0,  3, 0, 0, 0, 0 },
        { 3, 0,  3, 0, 0, 0, 0 },
    };
    Process rr_procs[] = {
        { 1, 0, 24, 0, 0, 0, 0 },
        { 2, 0,  3, 0, 0, 0, 0 },
        { 3, 0,  3, 0, 0, 0, 0 },
    };

    fcfs(fcfs_procs, 3);
    round_robin(rr_procs, 3, 4);
    return 0;
}

Use code with caution.

💻 CODE DISSECTION: TRACING SCHEDULING ARITHMETIC

Walking the Scheduling Traces

if (time < procs[i].arrival)

FCFS's idle handling. If no process has arrived yet, advance time to the next arrival. Simple, but preserves the convoy behavior.

procs[i].completion = time; time += burst

FCFS's execution. Each process runs to completion, no preemption. This is exactly what causes the convoy effect.

waiting = turnaround − burst

The metric derivation. Once completion is known, wait and turnaround follow directly.

run_time = min(remaining, Q)

RR's quantum. Each process runs for the smaller of the two — never more than Q, possibly less if it finishes early.

remaining -= run_time

RR's progress. A 24ms process with Q=4 has 20ms remaining after one quantum, 16 after two, etc.

The Verdict

With FCFS: Average WT = 17ms, Average TAT = 27ms. With RR: Average WT ≈ 5.67ms, Average TAT ≈ 15.67ms. RR's dramatic improvement despite using the same processes demonstrates the power of preemption.

🏆 RETROSPECTIVE: SYLLABUS DISSECTION SUMMARY

Grand Lecture Summary

01

FCFS is trivially simple but suffers from the convoy effect — short processes trapped behind long ones. SJF is mathematically optimal for average wait time but requires impossible prior knowledge. Round Robin adds preemption via time quantum, dramatically improving responsiveness at the cost of slightly higher average wait.

02

Preemption (via the timer interrupt) is the boundary between batch and interactive computing. It requires the OS to save and restore PCB state on every switch (from L06) — a cost that the quantum size must be tuned against.

03
